# Forbes Billionaire Splice Resources

`forbes_billionaires_2022_2025.csv` holds the synthetic billionaire tax-unit
inputs: one row per Forbes billionaire per list year. It is generated by
`build_forbes_input.sh` (see below); do not hand-edit.

Required columns:

- `year`: Forbes list year. The v1 splice is wired for 2022-2025.
- `rank`: rank within year. RE-RANKED within the US subset (1..N by net
  worth), not the raw global Forbes rank — BSYZ rank groups are US-tax-based.
- `name`: Forbes display name retained in output metadata.
- `net_worth`: net worth in dollars, not millions or billions.
- `source_category`: Forbes industry (falling back to source/company, then
  "unknown"). Audit metadata only.

Optional columns:

- `weight`: synthetic record weight. Defaults to 1 when absent.
- `age1`, `male1`, `country`, `sector`, `notes`, `forbes_uri`: retained for
  audit/input hygiene, but not consumed by v1.

## build_forbes_input.sh

Regenerates `forbes_billionaires_2022_2025.csv` from the komed3/rtb-api
Forbes real-time-billionaires snapshots (MIT licensed,
https://github.com/komed3/rtb-api). One year-end (Dec 31) snapshot per list
year; filters to US citizens; re-ranks within the US subset; converts net
worth from the source's $millions to dollars. Requires `curl` and `jq`. Run
from the repo root:

    bash resources/forbes/build_forbes_input.sh

## forbes_profiles.csv

Per-profile enrichment for the v2 (assemble-don't-copy) splice: one row per
unique `forbes_uri`, generated by `build_forbes_profiles.sh`. Joined onto the
per-year base by `read_forbes_input()` on `forbes_uri`. Do not hand-edit.

Pulled **once, latest snapshot** per profile — not per year. `/assets` is
latest-only at the source (v2 scales the latest composition to each year's
net worth); `/info` fields are stable (birthDate, gender) or accepted at their
latest point-in-time value (maritalStatus, children).

Columns:

- `uri`: join key (matches `forbes_uri` in the per-year base).
- `birth_date`: ISO date from `/info`; R derives `age1 = list_year - birth_year`.
- `gender`: `m` / `w` from `/info`; R maps to `male1`.
- `marital_status`: raw Forbes string (`Married`, `Divorced`, `Widowed,
  Remarried`, `In Relationship`, ...). R maps to filing status.
- `children`: integer count from `/info`; R derives dependents.
- `family`: `true` for family-fortune entries (e.g. a "… family" listing).
- `self_made`: `selfMade._is` (true for self-made; absent → false).
- `self_made_type`: `selfMade.type` (`self-made` vs `inherited` / `inherited
  and growing`). **This is the founder signal the basis model keys on**, not
  `self_made` — inherited profiles set `_is` absent but carry a `type`.
- `residence_state`: `/info` residence state (audit; light use).
- `industry`: `;`-joined `/info` industry tags (real-estate fallback for the
  private residual).
- `n_assets`: number of `/assets` holding rows.
- `public_equity_interactive`: Σ `numberOfShares × sharePrice` over holdings
  with `interactive=true` — the Forbes live-tracker direct stake.
- `public_equity_all`: Σ over **all** holding rows (options + share classes).

Reconciliation rule (in R): public-equity value = `interactive` if `> 0`, else
`_all`. Some inherited holders (e.g. Walton/WMT) carry their entire stake as a
single `interactive=false` row, so `interactive` alone would zero them out.
Holdings are valued in native currency (exchangeRate omitted): ~all
US-billionaire holdings are USD, and the composition is reconciled to
`net_worth` so only the public/total ratio matters. Foreign holdings are a
documented minor gap.

## bsyz_fiscal_income_params.csv

Maps Forbes wealth to fiscal income using BSYZ 2025 Table 1. Stored WIDE:
one row per rank group, with a column per income category.

- `rank_group`, `rank_min`, `rank_max`: the rank band (top100 / next300 /
  rest_billionaires) and its inclusive US-rank bounds.
- `fiscal_income_to_wealth`: fiscal income divided by Forbes wealth, per
  group.
- one column per income category (`capital_gains`, `dividends`, `interest`,
  `business`, `rent_estate_other`, `wages_pensions`): that category's share
  of fiscal income. Shares may be negative (billionaires net-report business
  losses) and are row-normalized to sum to 1 on read.

Wide format makes the rank_group join in `forbes_target_categories`
many-to-one (each billionaire matches its single group row), so there is no
fan-out and a stray duplicate row cannot silently double-count a category.

The paper reports separate values for the top 100 and next 300. The
`rest_billionaires` group currently reuses the next-300 values as a v1
simplification until we choose a better extrapolation below rank 400.
