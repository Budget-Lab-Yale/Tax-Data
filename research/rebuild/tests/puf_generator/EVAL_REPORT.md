# Test 1: evaluation of generated PUF records

Part C of `SPEC.md`. This file explains each measure, gives the formula for
approximate AGI, and reports results. The tables between the
`GENERATED` markers are written by `evaluate.py`; re-running it with
`--update-report` replaces them, so the model's column appears without
editing by hand (see "Re-running" at the end).

## Summary

**What is compared.** Each candidate file is compared with the 20,768 held-out
test records (10% of the PUF, never used for training). Four candidates:

- **floor**: the 166,156 training records themselves. Real records, so any gap
  to the test records is sampling noise. No method can be expected to do
  better on average.
- **floor_binned**: the same training records turned into tokens and back with
  part A's tokenizer (each amount replaced by a random draw within its bin).
  This is the floor after binning, before any model: the gap the model inherits
  from the binning alone.
- **independent**: every variable drawn on its own from its weighted
  distribution in the training records. Each variable's distribution is right;
  every relationship between variables is lost. This is the "know nothing about
  the joint distribution" reference.
- **model** (when run): the records generated by part B's model, as many as the
  training records.

A useful reading of every row is: where does the model sit between the floor
(sampling noise only) and independent (no relationships at all)?

**Results so far.** Part B's generated file did not exist when this report was
written (21:05, 2026-10-08), so only the references are shown. Run of
2026-10-08 on part A's final files, label `baseline`, 155 seconds.

Reading the references:

- The floor sits close to zero on every distance measure; the remaining gap is
  the noise of a 20,768-record test sample: a median TVD across the 780
  two-way tables of 0.012, a classifier AUC of 0.505, and an AGI-gap
  distribution within 0.011 of the test records'.
- The independent file matches every single variable as well as the floor does
  (by construction), but is far from the test records on anything involving
  two or more variables at once: median two-way TVD 0.028 and 90th percentile
  0.137 (floor 0.022), the largest being AGI × wages at 0.570; nonzero-pattern
  TVD 0.674 (floor 0.080); profiles off by 10.1 percentage points on average
  (floor 0.7). Only 0.1% of its records have AGI within 0.2% of the
  approximate AGI (test records 62%). A classifier separates it from real
  records completely (AUC 1.000). Its top shares happen to be close to the
  test records' (19.7% and 8.8% against 19.5% and 8.9%), because the top
  share of AGI depends mainly on AGI's own distribution.
- The binned floor shows what binning alone costs. It is the same as the
  floor on every measure built from bins and shares (two-way, three-way,
  patterns, profiles, top, classifier AUC 0.508). It differs in AGI
  consistency: because AGI and each component are drawn separately within
  their bins, only 8.3% of binned records have AGI within 0.2% of the
  approximate AGI (real records 62%) and 61% within 2% (real 81%); TVD of the
  gap distribution 0.537. A model that generates tokens and decodes them
  cannot do better than this on AGI consistency, so its AGI-consistency
  numbers should be read against the binned floor, not the floor.
- The binned floor also shows which copying measure works for the model. Its
  records are exact token copies of training records (99.9% identical on
  tokens), yet only 0.05% are identical on dollar values and only 6.6% fall
  within the test records' 10th-percentile distance, because decoding moves
  each amount within its bin. The token-identity check detects copying after
  decoding; the value-based checks largely do not, though a median
  nearest-record distance far below the test records' (0.01 of it here) is
  still a strong sign.
- The copying measures for real test records are not zero: about 7.5% of test
  records are identical, value for value, to some training record. These are
  low-income returns from the lowest sampling stratum (weight about 1,432)
  with exactly two nonzero amounts, AGI and wages, rounded to the nearest
  hundred dollars (the PUF rounds most amounts). Such duplicates are genuine,
  not copying, so a model's share of identical records should be compared with
  this level, not with zero. On tokens, 12.5% of test records match some
  training record exactly; that is the reference for the model's token
  identity share.

## The candidates in more detail

**Floor.** The training file is eight times the size of the test file, the
same size as the model's generated file, so the comparison is like-for-like
with the model. The floor's distances are mostly the test file's own sampling
noise.

**Binned floor.** `decode(encode(train))` with part A's `tokenizer.py`, seed
20261010. Weight tokens are exact values, so the weights are unchanged.
Amounts in the zero token and in "point" tokens (single values held by many
records) are exact; others are drawn within their bin and rounded down to
whole dollars.

**Independent.** For each variable separately, 166,156 values drawn with
replacement from the training records with probability proportional to the
record weight, so each variable's weighted distribution matches train in
expectation. The weight column itself is drawn from the training weights as
they occur in the file (unweighted), so that the weights look like real PUF
weights to the classifier; because it is drawn independently of everything
else, it does not distort the weighted distributions. Seed 20261009.

**Weights.** All distribution comparisons use each file's own `weight`
column, normalised to sum to one. The total weight of each file relative to
the training file is reported in the first row of the headline table (the
test file is 10% of the PUF, the training file 80%, so the test file's total
is about 12.5% of train's).

## The measures

Terms used throughout:

- **Total variation distance (TVD)** between two tables of shares: half the sum
  over cells of the absolute difference in cell shares. It is the largest
  difference in the share of the population that the two files can assign to
  any set of cells. 0 means identical tables, 1 means no overlap.
- **Weighted quantile**: the smallest value at which the weighted cumulative
  share reaches the given fraction (for example, the weighted median is the
  smallest value with at least half the weight at or below it).
- **AGI percentile group**: each record's position in its own file's weighted
  AGI distribution, grouped into deciles, with the top decile split into
  P90–99, P99–99.9 and the top 0.1%. Each file is ranked on its own AGI, so the
  groups hold the same share of weight in every file; differences in the level
  of AGI itself show up under the single-variable measures instead.

**1. Single variables.** For each amount: weighted share at zero, share
negative, weighted quantiles (10th, 25th, 50th, 75th, 90th, 99th, 99.9th) and
weighted mean. For categorical variables: the share in each category. One
summary number per variable is the TVD between the candidate's and the test
records' distribution over the bins described next. Files:
`single_variables.csv`, `marginal_tvd.csv`.

**2. Two- and three-variable tables.** Each amount is put in bins: negative,
zero, and the ten deciles of positive values among the test records
(weighted). The weight is binned into deciles in the same way. Categorical
variables keep their own categories (with "missing", coded -1, as one). For
every pair of the 40 variables (780 pairs), the TVD between the candidate's
weighted two-way table and the test records' table. Reported: the
distribution across pairs and the pairs furthest above the floor. Three-way
tables for nine combinations that matter for tax:

| Three-way table | Why |
|---|---|
| AGI band × filing status × sign of net capital gain (P22250 + P23250) | who realises gains and losses |
| AGI band × deduction type (FDED) × age range | itemising by income and age |
| wage decile × dividend decile × filing status | labour and capital income together |
| AGI band × sign of Schedule C × sign of partnership/S corporation income | business income structure |
| AGI band × has Social Security × age range | retirement income |
| AGI band × EITC children × filing status | EITC population |
| AGI band × deduction type × state and local income/sales tax band | SALT among itemisers |
| AGI band × CTC children × exemptions | family structure |
| wage band × taxable pension band × age range | transition to retirement |

"AGI band" is the AGI binning above (negative, zero, deciles of positive).
Files: `pair_tvd.csv`, `pair_tvd_summary.csv`, `triple_tvd.csv`,
`pair_tvd_cdf.png`.

**3. Which incomes appear together.** The 15 income variables most often
nonzero among the test records are chosen (listed in the detail table). Each
record has a pattern: which of the 15 are nonzero. The measure is the TVD
between the weighted frequencies of patterns, plus the number of distinct
patterns and the weight in patterns that never occur in the test records.
The training file has more distinct patterns than the test file only because
it is eight times larger. File: `nonzero_patterns_top40.csv`.

**4. Conditional profiles.** The weighted share nonzero and weighted mean of
each amount within each AGI percentile group. Plots: `profiles_share_nonzero.png`
and `profiles_mean.png` (one panel per variable; the mean is on a scale that is
linear near zero and logarithmic beyond $100). Headline number: the mean,
over 30 amounts × 12 groups, of the absolute gap in share nonzero, in
percentage points. File: `profiles.csv`.

**5. The top.** For AGI and each amount, the share of the positive amounts
held by records above the file's own 99th and 99.9th AGI percentiles. For AGI
the share of net AGI (negatives included) is also in `top_shares.csv` as
`E00100_net`.

**6. Classifier test.** A gradient-boosted tree classifier (scikit-learn's
`HistGradientBoostingClassifier`: a sequence of small decision trees, each
fitted to the errors of the ones before) is trained to tell candidate records
from test records. Balanced samples: all test records and the same number of
candidate records drawn at random; 70% to train the classifier, 30% held out.
All 40 variables are features, including the weight; records are not
weighted. Reported on the held-out part:

- **Accuracy**: share classified correctly (0.5 is guessing).
- **AUC** (area under the ROC curve): the probability that the classifier
  scores a randomly chosen candidate record as more likely "candidate" than a
  randomly chosen test record. 0.5 means the two files cannot be told apart;
  1 means they are perfectly separated.
- **Permutation importance**: for each variable, the fall in AUC when that
  variable's values are shuffled among the held-out records, which breaks its
  link to everything else. Large falls mark the variables the classifier uses
  to spot candidate records. Averaged over five shuffles.

Files: `classifier.csv`, `classifier_importance.csv`,
`classifier_importance.png`.

**7. AGI consistency.** AGI (`E00100`) is generated like any other variable,
so it need not equal the sum of the generated components. The measure: the
gap between reported AGI and an approximate AGI built from the components
(formula below), divided by the larger of |AGI| and $1,000, and grouped into
nine bands from "below −50%" to "above +50%". The real records do not satisfy
the formula exactly either (see below), so what matters is whether the
candidate's distribution of gaps looks like the test records'. Reported: the
shares within 0.2% and within 2%, and the TVD across the nine bands. Files:
`agi_gap_bins.csv`, `agi_gap_quantiles.csv`, `agi_gap.png`.

**8. Copying.** Whether a candidate reproduces training records. Each of the
40 variables is replaced by its rank among the training records (its
mid-rank, scaled to 0–1, so every variable counts equally regardless of its
dollar scale). For each candidate record, the Euclidean distance in that rank
space to its nearest training record (exact search over all training records).
The reference is the same distance for the real test records: a real record
from the same population is typically that close to some training record
without being a copy. Reported: the ratio of the candidate's median distance
to the test records' median, the share of candidate records at or below the
test records' 10th-percentile distance (10% for the test records by
construction; much more than 10% suggests copying), and two identity checks:
the share of candidate records identical to a training record on every value,
and on every token (after encoding both with part A's tokenizer). The token
check is the relevant one for the model, because decoding draws a value
within each bin, so a model that reproduced a training record's tokens would
almost never reproduce its exact dollar values. For the floor, the copying
measures are those of the test records. Files:
`copying_distance_quantiles.csv`, `copying_distance_cdf.png`.

## Approximate AGI

Built from the 2015 Form 1040 lines and the PUF booklet's record layout, using
only the variables in this test. All amounts in dollars; losses in `E25860`
and `E26400` are stored as positive numbers.

```
approximate AGI =
    E00200                    wages
  + E00300                    taxable interest
  + E00600                    ordinary dividends
  + E00900                    Schedule C net profit or loss
  + max(P22250 + P23250, L)   Schedule D net gain, loss limited to L = -3,000
                              (-1,500 if married filing separately)
  + E01100                    capital gain distributions reported on Form 1040
  + E01400                    taxable IRA distributions
  + E01700                    taxable pensions and annuities
  + E02100                    Schedule F net profit or loss
  + E02300                    unemployment compensation
  + E25850 - E25860           rent and royalty net income minus net loss
  + E26270                    partnership and S corporation net income or loss
  + E26390 - E26400           estate and trust income minus loss
  - E03150                    IRA deduction
  - E03210                    student loan interest deduction
  - E03270                    self-employed health insurance deduction
  - SE                        deduction for half of self-employment tax
  + TSS                       taxable Social Security
```

- **SE** = half of 2015 self-employment tax on net earnings
  N = 0.9235 × max(E00900 + E02100, 0) (zero if N < $400):
  0.124 × min(N, max(118,500 − E00200, 0)) + 0.029 × N, halved.
- **TSS** follows the Form 1040 Social Security worksheet with gross benefits
  `E02400`. Provisional income P = (all other terms above) + `E00400`
  (tax-exempt interest) + 0.5 × `E02400`. Base amounts B1/B2 are
  $25,000/$34,000 ($32,000/$44,000 joint; 0/0 married filing separately).
  TSS = 0 if P ≤ B1; min(0.5(P − B1), 0.5 × benefits) if B1 < P ≤ B2;
  otherwise min(0.85(P − B2) + min(0.5(B2 − B1), 0.5 × benefits),
  0.85 × benefits).

Left out because they are not among the test's variables: state income tax
refunds (`E00700`), alimony received and paid (`E00800`, `E03500`), other gains
(`E01200`), farm rental (`E27200`), other income on line 21 (not on the PUF),
and the smaller adjustments (educator expenses, tuition, domestic production,
HSA, Keogh, early-withdrawal penalty). The passive-loss limit on rental
losses and the self-employment tax on partnership income are also ignored.

How well the formula works on the real 2015 PUF (all 207,692 non-aggregate
records, weighted): reported AGI is within 0.2% of the approximate AGI for 61%
of returns and within 2% for 81%. Even the sum of every published PUF
component and adjustment, with the PUF's own taxable Social Security,
matches reported AGI within 0.2% for only 69% of returns and to the dollar
for 41%, because the PUF rounds amounts (most wages and AGI to the nearest
hundred dollars) and omits line 21. The test's single comparison is
therefore between distributions of the gap, not whether the gap is zero.

## Notes

- **Test sample size.** The test file has 20,768 records, so any table with
  many thin cells has a TVD of a few hundredths even between two real samples.
  This is why every number is read against the floor rather than against
  zero.
- **The top of the distribution.** The PUF samples high-income returns at much
  higher rates (weights near 1 at the very top), so the test file holds
  several hundred records above the 99.9th AGI percentile, enough for the top
  shares to be estimated. The demographic file covers none of the records
  with weight below 200 (part A's data report), so `AGERANGE`, `GENDER` and
  `EARNSPLIT` are "missing" for almost all of the top.
- **The independent file and the top.** Because it draws each variable in
  proportion to weight, the independent file holds few records with the large
  values found in the top (low-weight) records; its top shares are close to
  the test records' only on average and are noisier.
- **Seeds.** Evaluation seed 20261008 (recorded in `summary.json`); the
  independent file uses 20261009, the binned floor 20261010; the classifier
  and its permutation importance use fixed offsets of the same seed.
- **Development.** The suite was first developed on a temporary split built
  directly from the raw PUF files (under `$S/eval/dev/`), including two
  checks of the measures themselves: the validation records as a candidate
  (they behave like the floor) and a sample of training records as a
  candidate (the copying measures flag 100% identical records and the median
  nearest-record distance falls to zero).

## Re-running

Every run goes through Slurm. From `$S = /nfs/roberts/scratch/pi_nrs36/jar335/puf_generator`:

```
CODE=/nfs/roberts/project/pi_nrs36/jar335/Repositories/Tax-Data/research/rebuild/tests/puf_generator
# references only
sbatch $CODE/evaluate.sbatch --label baseline --update-report $CODE/EVAL_REPORT.md
# the model (floor and references come from the cache)
sbatch $CODE/evaluate.sbatch --synthetic $S/model/synthetic.parquet --label model \
       --update-report $CODE/EVAL_REPORT.md
```

Outputs go to `$S/eval/<label>/`: `summary.json`, the CSV tables, the PNG
plots and `report_tables.md` (the generated tables). The references are
cached in `$S/eval/_cache/`, keyed on the data files and on the source of
`evaluate.py`, so they are recomputed only when either changes. A full run
takes about two to three minutes on 8 CPU cores. After re-running with the
model, the prose in the Summary should be revised to describe the model's
column.
